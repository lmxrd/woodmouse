# woodmouse-client

The TypeScript client for the Woodmouse API. 

This package is generated by [`@hey-api/openapi-ts`](https://heyapi.dev/).

## Installation

The package is consumed from within the frontend workspace; it is not
published. Peer dependencies:

- `@tanstack/react-query` — only needed if you use the `react-query` export
- `zod` — only needed if you use the `zod` export

## Exports

| Export            | What it gives you                                                       |
| ----------------- | ----------------------------------------------------------------------- |
| `woodmouse-client` | All operations as plain async functions, plus every generated type       |
| `woodmouse-client/client` | The underlying client instance (`client`, `ClientOptions`) — use it to configure `baseUrl`, credentials and interceptors once at startup |
| `woodmouse-client/react-query` | TanStack Query helpers: `xxxOptions`/`xxxQueryKey` for queries, `xxxMutation` for mutations |
| `woodmouse-client/sdk` | The raw operation functions only (same as the root export)              |
| `woodmouse-client/types` | Generated types only                                                    |
| `woodmouse-client/zod` | Zod schemas for the API types (runtime validation)                     |
| `woodmouse-client/spec` | The OpenAPI spec the code was generated from (`source.json`)            |

## Configuring the client

Configure once, before any request fires. Authentication is a session
cookie, so point the client at your API and include credentials:

```ts
import { client } from "woodmouse-client/client";

client.setConfig({
  baseUrl: import.meta.env.VITE_API_URL ?? "",
  credentials: "include",
});

client.interceptors.response.use((response) => {
  // e.g. detect 401s and treat them as an expired session
  return response;
});
```

Every operation accepts optional per-call overrides (`baseUrl`, `headers`,
`signal`, `throwOnError`, ...) and an alternate `client` instance.

## Logging in

`login` posts credentials and sets the session cookie. Use it directly:

```ts
import { login } from "woodmouse-client";

const { data: user, error } = await login({
  body: { email, password },
});
```

Or with TanStack Query:

```tsx
import { useMutation } from "@tanstack/react-query"
import { loginMutation } from "woodmouse-client/react-query";

const login = useMutation(loginMutation());
login.mutate({ body: { email, password } });
```

On success you get the logged-in user back; the cookie keeps subsequent calls
authenticated. `logout` ends the session, and a `me` query is available for
checking the current user / guarding routes.

## Using the rest of the API

Every endpoint in the spec gets the same shape of generated code, so this
README intentionally stays static as the API evolves:

- **Plain functions** — `import { listTasks } from "woodmouse-client"` and
  `await listTasks({ path: { ... }, query: { ... } })`. Calls return
  `{ data, error, response }`; they only throw when `throwOnError: true`.
- **Queries** — `import { listTasksOptions } from "woodmouse-client/react-query"`
  and pass the options to `useQuery`/`queryClient.ensureQueryData`. Each has a
  matching `xxxQueryKey` for cache reads and invalidation.
- **Mutations** — `import { createTaskMutation } from "woodmouse-client/react-query"`
  and pass it to `useMutation`.
- **Types** — request/response types (`XxxData`, `XxxResponse`, ...) come from
  `woodmouse-client/types` (also re-exported at the root).
- **Zod Schemas** — schemas (`XxxData`, `XxxResponse`, ...) come from
  `woodmouse-client/zod`.

For the exact set of operations and their parameters, rely on editor
autocomplete or the generated files themselves — they are the source of
truth.
